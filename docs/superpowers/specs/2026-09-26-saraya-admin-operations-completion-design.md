# اكتمال عمليات إدارة سرايا سكوير

## الهدف

تحويل جميع صفحات لوحة إدارة سرايا سكوير من صفحات عرض جزئية إلى وحدات تشغيلية مكتملة، مع إبقاء كل إجراء ظاهر مرتبطًا بخدمة حقيقية وقاعدة البيانات والصلاحيات وسجل التدقيق.

## النطاق

تشمل المرحلة لوحة الإدارة فقط. تبقى بوابة المستأجر مرحلة لاحقة مستقلة، مع الحفاظ على صلاحيات المالك والمستأجر الحالية وعدم توسيعها ضمن هذه المرحلة.

## الحالة الحالية

- لوحة المعلومات: تعمل للعرض والتنقل.
- العقارات والوحدات والعملاء والفريق: تدعم الإضافة والتعديل وإلغاء التنشيط عبر واجهة الإدارة المشتركة.
- الحساب: يدعم تعديل الملف وكلمة المرور.
- الفواتير: عرض ودفع عند وجود رابط آمن، دون إنشاء أو تعديل إداري.
- العناوين الافتراضية: عرض فقط.
- قاعات الاجتماعات: عرض فقط رغم وجود خدمات خادم للحجوزات وتحديث القاعات.
- العقود: عرض وإجراءات خادم للحالة، دون واجهة إنشاء أو إدارة دورة العقد.
- الصيانة: عرض فقط.
- المستندات: عرض فقط.
- التقارير: عنصر تنقل بلا صفحة فعلية.

## التصميم الوظيفي

### العناوين الافتراضية

- إنشاء عنوان من مخزون الخمسين أو تعديل بياناته التشغيلية.
- ربط العنوان بعميل، وتسجيل الاسم التجاري والرسوم والفترة والحالة.
- تحرير الاشتراك وتعليقه وإنهاؤه مع تأكيد قبل الإجراء.
- منع تجاوز سعة المخزون ومنع تكرار الرمز.

### قاعات الاجتماعات والحجوزات

- إضافة القاعتين أو تعديل الاسم والسعة والسعر وساعات التشغيل والحالة.
- إنشاء حجز إداري لعميل، وتعديل الحجز قبل بدايته، واعتماده أو رفضه أو إلغاؤه.
- منع تعارض الحجوزات وتجاوز ساعات التشغيل.

### العقود

- إنشاء عقد من وحدة وعميل وشروط مالية وفترة ودورية استحقاق.
- عرض الإجراءات المسموحة فقط حسب حالة العقد: إرسال، اعتماد، رفض، طلب تجديد، قرار التجديد، إنهاء، وإغلاق.
- منع تعديل النسخة المعتمدة؛ أي تغيير مالي أو زمني ينشئ نسخة عقد جديدة.
- عرض سجل الحالة والتغييرات داخل تفاصيل العقد.

### الفواتير والتحصيل

- إنشاء فاتورة إدارية مرتبطة بعقد أو خدمة، وتعديل المسودة فقط.
- اعتماد الفاتورة، تسجيل دفعة، إصدار إيصال، وإلغاء الفاتورة وفق الصلاحية والحالة.
- إبقاء الدفع الإلكتروني متاحًا فقط عند وجود رابط آمن صادر من الخادم.
- احتساب الأرصدة من السجلات المالية الفعلية دون قيم تخمينية في الواجهة.

### الصيانة

- إنشاء بلاغ وربطه بوحدة وعميل، مع الأولوية والوصف.
- تعديل الإسناد والحالة والمصروفات، وإغلاق البلاغ بعد الحل.
- تسجيل كل انتقال حالة ومصروف في السجل الزمني.

### المستندات

- رفع PDF وJPG وPNG حتى 20 ميجابايت عبر التخزين الخاص الموجود في الخادم.
- ربط الملف بالعقار أو الوحدة أو العميل أو العقد أو البلاغ.
- تعديل العنوان والتصنيف وتاريخ الانتهاء، وأرشفة الملف بدل حذفه نهائيًا.
- تنزيل المستند عبر رابط قصير الصلاحية بعد التحقق من الصلاحية.

### التقارير

- صفحة تقارير فعلية تشمل الإشغال، الاستحقاقات، التحصيل، المتأخرات، العقود، الصيانة، والعناوين الافتراضية.
- مرشحات فترة زمنية وحالة ووحدة وعميل.
- عرض المؤشرات والجداول من بيانات الخادم مع تصدير CSV؛ لا يشمل PDF في هذه المرحلة.

## تجربة الاستخدام

- استخدام نافذة جانبية موحدة للإضافة والتعديل على الكمبيوتر، ونافذة كاملة الارتفاع على الجوال.
- عرض زر الإضافة فقط للأدوار المخولة، وإخفاء الإجراءات غير المسموحة حسب حالة السجل.
- تأكيد الإجراءات المؤثرة مثل الإلغاء والإنهاء والأرشفة.
- رسائل نجاح وفشل عربية وإنجليزية، مع إعادة المحاولة وعدم عرض تفاصيل الخادم الحساسة.
- دعم RTL وLTR، والجداول على الشاشات الواسعة والبطاقات على الجوال.

## الصلاحيات

- مدير النظام: جميع الإجراءات.
- مدير المجمع: جميع العمليات اليومية باستثناء إدارة مدير النظام.
- المحاسب: الفواتير والتحصيل والتقارير المالية.
- فريق الصيانة: البلاغات والمصروفات والمستندات المرتبطة بالصيانة.
- المالك والمستأجر: لا تضاف لهما إجراءات جديدة في هذه المرحلة.

## البيانات والتدقيق

- كل سجل يبقى مقيدًا بمعرف العقار في قاعدة البيانات والخدمة.
- كل إجراء تغييري يسجل المستخدم والوقت ونوع العملية والكيان والحالة السابقة واللاحقة.
- تستخدم المعاملات عند إنشاء عقد وفاتورة وجدول استحقاق أو عند تسجيل دفعة وإيصال.
- لا تحذف السجلات المالية أو العقود أو المستندات نهائيًا من واجهة الإدارة.

## معالجة الأخطاء

- التحقق في الواجهة لتحسين التجربة، والتحقق الإلزامي في الخادم لحماية البيانات.
- تعارض الحجز أو تكرار الرمز أو انتقال الحالة غير المسموح يعيد خطأ مجال واضحًا ومترجمًا.
- فشل الرفع أو الدفع لا ينشئ سجلًا مكتملًا جزئيًا.

## الاختبارات ومعايير القبول

- اختبار خدمة ومسار API لكل عملية إنشاء وتعديل وانتقال حالة وصلاحية.
- اختبار واجهة لكل صفحة على سطح المكتب والجوال بالعربية والإنجليزية.
- اختبار قبول إداري يمر عبر إنشاء عميل ووحدة وعقد وفاتورة ودفعة وصيانة ومستند وتقرير.
- كل عناصر التنقل تفتح صفحة فعلية، وكل زر ظاهر ينفذ إجراءً حقيقيًا.
- نجاح تحليل Flutter واختباراته، واختبارات الخادم وفحص TypeScript، وبناء الويب.
- فحص يدوي في المتصفح لكل صفحة دون أخطاء أو تحذيرات في وحدة التحكم.

## خارج النطاق

- تطبيقات المتاجر والنشر العام.
- توسيع بوابة المستأجر أو المالك.
- تكامل توقيع إلكتروني أو بوابة دفع جديدة غير الموجودة حاليًا.
- تصدير PDF للتقارير.
